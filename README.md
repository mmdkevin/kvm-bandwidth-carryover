# KVM Bandwidth Carryover — v2.0.0

مدیریت ماندهٔ ترافیک Virtualizor KVM روی AlmaLinux، همراه با منوی نصب و مدیریت.
هر افت مشاهده‌شدهٔ شمارنده ریست محسوب می‌شود. برنامه فقط Bandwidth را ویرایش می‌کند.

## نصب یا ارتقای نسخهٔ قبلی

با root روی سرور اصلی اجرا کنید؛ سپس گزینهٔ 1 را انتخاب کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/mmdkevin/kvm-bandwidth-carryover/main/install.sh)
```

در نصب اول مبنای فعلی ثبت می‌شود. در ارتقا، سابقه و مانده‌ها حفظ و قبل از تغییر فایل‌ها پشتیبان تهیه می‌شود.
برای اجرای بدون منو، در انتهای دستور بالا `install` یا `upgrade` بنویسید.

## دستورات

| دستور | کار |
|---|---|
| `kvm-bw` | منوی مدیریت |
| `kvm-bw status` | نسخه، Cron، آخرین اجرای موفق و وضعیت VPSها |
| `kvm-bw commands` | تمام دستورات |
| `kvm-bw preview` | پیش‌نمایش اصلاح سهمیه بدون ذخیره یا ویرایش |
| `kvm-bw run` | یک بررسی واقعی همین حالا |
| `kvm-bw start` / `kvm-bw stop` | فعال‌سازی یا توقف Cron خود برنامه |
| `kvm-bw logs` | نمایش لاگ‌های اخیر |
| `kvm-bw doctor` | بررسی وابستگی‌ها، داده‌ها و اتصال خواندنی API |
| `kvm-bw backup` | پشتیبان از مبنا، برنامه و تنظیمات کار |
| `kvm-bw upgrade` | دریافت نسخهٔ جدید از همین مخزن |
| `kvm-bw uninstall` | حذف برنامه و Cron؛ داده‌ها و سهمیه‌های پنل حفظ می‌شوند |

دستور قدیمی `reset-carryover` هم با همین گزینه‌ها کار می‌کند.
`status --json` خروجی قابل‌خواندن برای ابزارهای مانیتورینگ می‌دهد.

## نکات ضروری

- ریست دستی نزنید؛ برنامه آن را هم ریست دوره‌ای حساب می‌کند.
- داده‌های `/var/lib/reset-carryover` را حذف نکنید. حذف برنامه این داده‌ها را پاک نمی‌کند.
- تغییر سقف، قطع و تعلیق را به خود Virtualizor واگذار می‌کند؛ برنامه دستور کنترل شبکه یا خاموش‌کردن VM ندارد.
- برای ماندهٔ زیر 1GB پیش‌فرض حداقل 1GB است؛ صفر در پنل نامحدود است. سیاست را با `kvm-bw policy hold` می‌توان به توقف اصلاح زیر 1GB تغییر داد.
- تشخیص بر پایهٔ افت قابل‌مشاهده است؛ ریست پنهان بین نمونه‌ها یا مصرف گزارش‌نشدهٔ انتهای دوره قابل بازیابی قطعی نیست.
- `resync VPS_ID` پس از بررسی اعداد، وضعیت فعلی پنل را مبنای جدید می‌پذیرد؛ خودکار برای رفع خطا اجرا نمی‌شود.
